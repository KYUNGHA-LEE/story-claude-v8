## V8.10 (2026-11-20)

사용자 요청: (7단계 화면과 FlipBook 앱 화면을 보내며) "표지 이미지가 오른쪽으로 치우쳐 있잖아? 이거 플립북처럼 표지는 가운데 오게 해 줘."

- **표지와 뒤표지를 가운데에**: 넓은 화면(두 쪽 펼침)에서 책장 넘김 라이브러리는 표지를 오른쪽 칸, 뒤표지("끝")를 왼쪽 칸에 놓는다. 그래서 표지가 오른쪽으로 치우쳐 보였다. 이제 표지·뒤표지 한 장만 보일 때는 책을 반 쪽만큼 옮겨 그 장이 가운데에 온다. 책장을 넘기기 시작하면(누르거나 끌면) 펼친 자리로 미끄러져 돌아오고, 표지로 돌아오면 다시 가운데로 간다(0.6초). FlipBook 앱(story-flipbook)과 같은 방식이다.
  - **7단계 화면과 받는 플립북 파일(HTML) 둘 다** 바뀐다(둘이 `flipbookViewer` 하나를 같이 쓴다). 이미 받아 둔 플립북 파일은 그대로이므로 다시 받아야 한다. MP4 영상은 원래 표지가 가운데였다.
  - 좁은 화면(한 쪽씩 보기)은 원래 가운데라 옮기지 않는다.
  - 내부: 책을 `.fb-shift` 틀로 한 번 감싸 `translateX(±25%)`. 책장 상태(`changeState`: `user_fold`·`flipping` → 펼친 자리, `read` → 표지 자리)와 쪽 번호(`flip`)로 정한다. 옮긴 책의 빈 반쪽이 화면 밖으로 밀려 가로 스크롤이 생기지 않게 `.fb-stage`에 `overflow-x:clip`(옛 브라우저는 `hidden`)을 줬다. 창 크기가 바뀌어 책을 새로 만들 때는 미끄러지는 움직임 없이 바로 놓는다.

## V8.9 (2026-11-20)

사용자 요청: (7단계 표지 "나의 동화책" 화면을 보내며) "이 표지를 사용자가 표지 이미지를 업로드할 수 있게 해 줘."

- **표지 그림 올리기**: 전에는 표지가 늘 초록 바탕에 제목 글자(1단계 컨셉트, 없으면 "나의 동화책")였다. 이제 표지 그림을 올리면 **7단계 플립북 · 플립북 파일(HTML) · MP4 영상**의 표지가 그 그림으로 나온다. 올리지 않으면 전과 같은 제목 글자 표지.
  - **올리는 곳 두 군데(같은 그림)**: ① 5단계 맨 앞 **표지** 카드(눌러서 고르기·끌어다 놓기·바꾸기·빼기) ② 7단계 책 위 **표지 그림** 줄의 [표지 그림 고르기]·[표지 그림 빼기] — 7단계에서 바꾸면 책을 바로 다시 만든다.
  - **한꺼번에 올릴 때**: 파일 이름에 `표지`(표지판은 제외)나 `cover`가 있거나 번호가 0 하나뿐이면(`0.png`, `p00.jpg`) 표지로 넣고, 나머지를 쪽에 넣는다. 표지 파일을 먼저 골라내지 않으면 "이름의 쪽 번호대로 넣기"가 깨져서(번호 없는 파일이 섞임) 시각 순서로 넣게 되기 때문이다. 표지로 보이는 파일이 여럿이면 첫 번째만 넣고 알려 준다.
  - **그림 모양은 쪽 그림과 같은 규칙**: '그림에 원고가 들어 있나요?'가 아니요 → 책 크기에 맞게 자르고, 비율이 다르면 표지 카드의 좌우(위아래) 위치 막대로 자를 곳을 고른다. 네 → 자르지 않고 전체(남는 곳은 종이색).
  - **그림 표지에는 제목 글자를 얹지 않는다** (제가 정한 기본값 — 표지 그림에 제목이 이미 들어 있다고 봄). 제목 없는 그림 위에 글자를 얹는 선택지는 만들지 않았다.
  - **MP4 표지**: 그림만 영상은 화면 전체에(자르지 않음). 펼침면 영상은 화면이 두 쪽 너비라서 표지 한 쪽을 가운데에 놓고, 양옆에는 같은 그림을 흐리고 어둡게 깐다(흐리기를 못 하는 브라우저는 어두운 바탕). 표지 시간 2.5초는 그대로.
  - **JSON 저장·불러오기**: 표지 그림도 JSON에 들어간다(`media.img`의 `"0"`쪽, 쪽 그림과 같은 방식으로 줄여서). 저장 문구 예: "표지 그림 · 5단계 그림 10개 · 6단계 음성 6개 포함". 창 닫기 전 저장 안내도 표지를 함께 본다(표지를 올리거나 바꾸면 "저장 안 됨").
    - 불러올 때 파일에 그림이 있으면 **표지를 포함해 통째로** 파일의 것으로 바뀐다. 그래서 표지가 없는 파일(V8.6~V8.8에서 저장)을 불러오면 이 브라우저에 올려 둔 표지 그림은 빠진다(확인창에 "그림 4개(표지 포함)도 … 3개로 바뀝니다"). 그림이 아예 없는 파일(V8.5까지)은 표지도 건드리지 않는다.
    - V8.9에서 저장한 JSON을 V8.8까지의 앱(예: 받아 둔 옛 index.html)에서 열면 `"0"`쪽을 건너뛰어 표지만 빠진다(오류 없음 — 옛 코드의 `parseInt(n) < 1` 조건을 읽어 확인, 실제로 열어 보지는 않음).
  - [그림 모두 빼기]·[전체 초기화]는 표지 그림도 함께 뺀다(확인창에 적음).
  - 내부: 표지는 `media.img[0]`(`COVER_N`)에 둔다. 이야기 쪽이 1부터라 겹치지 않고, 브라우저 보관(IndexedDB `img:0`)·JSON·자를 위치가 쪽 그림과 같은 코드를 탄다. 5단계 카드의 그림 칸은 `addImgThumb()`로 묶어 표지 카드와 쪽 카드가 같이 쓴다.
  - 시험(내장 브라우저, PC, 로컬 서버 · 3쪽짜리 시험 책과 색칠한 시험 그림): `동화책 표지.png`(1000×600)+`1~3.png`를 한꺼번에 넣기 → 표지·1~3쪽에 들어감 / 좌우 위치 막대 → 7단계·새로고침 뒤에도 유지 / 7단계 [빼기] → 제목 글자 표지로, [고르기] → 그림 표지로(7단계에 머문 채) / 그림이 아닌 파일 → 7단계에 오류 문구 / JSON 저장 → 모두 빼기 → 불러오기로 표지·자를 위치 복원 / 글만 있는 파일·표지 없는 파일 불러오기 / 플립북 파일 안에 표지 JPG(책 비율 600×600)와 그림 표지 / MP4를 끝까지 만듦(1920×960, 13.5초, 약 5초 걸림)·표지 장면 그림 확인 / '네'로 바꾸면 표지도 자르지 않고 전체 / 1~7단계 화면·375px 폭 가로 넘침 없음 · 콘솔 오류 없음.
  - **확인 못 한 것**: 실제 표지 그림(사진·AI 그림)으로는 해 보지 않았다(색칠한 시험 그림만). 실제 파일 고르기 창을 눌러 고르는 것(시험에서는 고른 것처럼 넣음), 휴대폰·아이폰, 사용자 크롬, 받은 MP4를 다른 기기에서 재생. 내장 브라우저 창이 숨겨져 있어 만든 MP4를 다시 재생해 화면을 뽑아 보는 확인은 한 장면(표지)만 됐다.

## V8.8 (2026-11-19)

사용자 요청: "오디오북까지 만들면 mp4로 만들게 해 줘."

- **7단계에 [⬇ MP4 영상으로 받기]**: '플립북 파일로 받기' 아래에 상자를 하나 더 두었다. 누르면 표지(제목) → 1쪽 … N쪽 → 끝 순서의 영상 파일(MP4) 하나를 받는다. 쪽마다 6단계에 올린 음성을 1번부터 차례로 읽고, 다 읽으면 다음 쪽으로 넘어간다. 파일 이름 `제목_오디오북_YYYYMMDD_HHMM.mp4`.
  - **서버 없이 브라우저 안에서 만든다**(그림·음성을 밖으로 보내지 않음): 장면을 canvas에 그리고, WebCodecs로 H.264(영상)·AAC(음성, 48kHz 128kbps)로 압축한 뒤 mp4-muxer 5.2.1(MIT, jsDelivr CDN)로 MP4에 담는다. mp4-muxer는 버튼을 누를 때만 내려받는다(페이지 열 때는 안 받음).
  - **그림 모양은 '그림에 원고가 들어 있나요?' 답을 따른다**: 아니요 → 왼쪽 그림(5단계 자를 위치 그대로)·오른쪽 원고(플립북 글 쪽과 같은 여백·글자 비율, 넘치면 글자를 줄임)·가운데 옅은 접힘 그림자. 네 → 그림만, 자르지 않고 전체(남는 곳은 종이색).
  - **영상 크기**: 짧은 변 1080px, 긴 변 최대 1920px. 정사각형 책이면 펼침면 1920×960, 그림만 1080×1080. 30fps.
  - **시간**: 표지 2.5초 · 쪽이 바뀐 뒤 0.6초 쉬고 읽기 · 같은 쪽 음성 사이 0.35초 · 다 읽은 뒤 1초 · 음성 없는 쪽 3초 · 끝 2초. 쪽이 바뀔 때 0.4초 동안 겹쳐 바뀐다. 표지 제목은 두 줄이 되면 줄 길이를 고르게 나눈다.
  - 만드는 동안 "영상 만드는 중… 0:31 / 1:28 (45%)" 진행 표시, 버튼은 [■ 만들기 멈추기]로 바뀐다(누르면 파일을 받지 않고 멈춤). 그림·음성이 없는 쪽이 있으면 먼저 묻는다.
  - 브라우저가 H.264·AAC 압축을 못 하면 "컴퓨터의 크롬이나 엣지에서 해 주세요" 안내를 띄운다.
  - 시험(내장 브라우저 Chrome 156, PC): 토끼 책 6쪽(그림 PNG 6장, 음성 MP3 6개 11~13초) → 펼침면 1920×960 88초 **14.9MB, 약 20초 걸림** / 그림만 1080×1080 88초 **11.6MB, 약 15초**. 영상 길이 = 계획한 길이(87.9초). 영상에서 음성을 다시 꺼내 확인: 표지·쪽 앞뒤 쉼·끝은 무음, 읽는 구간만 소리. 표지·1쪽·바뀌는 순간·2쪽·5쪽·끝 화면을 꺼내 봄. 멈추기 시험(받지 않음). 375px 폭에서 1~7단계 가로 넘침 없음.
  - **확인 못 한 것**: 사용자 크롬·수강생 PC(특히 오래된 노트북에서 걸리는 시간), 휴대폰에서 만들기(안드로이드·아이폰은 지원 여부 모름 — 안 되면 위 안내가 뜸), 받은 MP4를 카톡으로 보내거나 휴대폰·아이폰에서 재생. H.264(High)+AAC는 흔한 형식이지만 실제 기기에서는 보지 않았다.
  - 처음 시험에서 88초에 30MB가 나와(2초마다 키프레임, 4.4Mbps) 키프레임을 5초마다·목표 비트레이트를 약 2.8Mbps로 낮췄다. 멈춘 그림이라 화질 차이는 눈으로 보이지 않았다.

## V8.7 (2026-11-19)

사용자 요청: "장면마다 사람들이 수정하고 싶어하는 부분들이 있고, 원고에도 복사버튼 만들어줘."

- **2단계 원고 카드에 [원고 복사]**: 그 쪽 원고 글만 복사한다(쪽 번호 없이). 4단계 장면 카드에는 전부터 [최종 프롬프트 복사]가 있었고 원고 카드에는 없었다.
- **카드에서 바로 고치기 — 4단계 [장면 수정], 2단계 [원고 수정]**: 전에는 고치려면 아래 원본 표(마크다운 표)를 직접 고쳐야 했다. 이제 카드의 수정 버튼을 누르면 본문 자리에 입력칸이 열리고, [수정 저장]을 누르면 원본 표의 그 줄에 되쓴 뒤 카드를 다시 그린다. Ctrl+Enter 저장, Esc 취소. 고치는 동안에는 그 카드의 복사·수정 버튼을 숨긴다(옛 글이 복사되지 않게).
  - 4단계는 장면 프롬프트 칸만 고친다. 사용 에셋 칸(캐릭터·장면·도구)은 그대로 둔다 — 형식이 까다로워 카드에서는 열지 않았다. 원본 표에서는 전처럼 고칠 수 있다.
  - 표 칸에는 줄바꿈과 `|`를 쓸 수 없어서, 저장할 때 줄바꿈은 띄어쓰기로, `|`는 `/`로 바꾼다.
  - 되쓰는 방법: `parseTableRows`가 각 줄에 원문의 줄 번호(`row.line`)를 달아 두고, `writeBackCell`이 그 줄의 마지막 칸만 바꾼다. 그 뒤 결과칸에 `input` 이벤트를 보내 자동 보관·카드 다시 그리기·"저장 안 됨" 표시가 결과칸을 직접 고쳤을 때와 똑같이 일어나게 했다.
  - **주의**: [원고 생성]·[장면 생성]을 다시 누르면 카드에서 고친 내용이 새 결과로 바뀐다(전부터 그랬음, 확인창 없음). 원고를 고쳐도 3단계 에셋·4단계 장면은 저절로 바뀌지 않는다.

## V8.6 (2026-11-19)

- **JSON 저장에 5단계 그림도 함께 들어간다**: V8.5에서 음성은 들어갔지만 그림은 빠져 있었다(사용자 보고: "음성은 들어왔는데 이미지가 빠져있어"). 이제 그림도 JSON의 `media.img`에 넣고, 불러올 때 5단계에 되살린다. 쪽·파일 이름·자를 위치(fx·fy)가 그대로 돌아온다. "그림에 원고가 들어 있나요?" 답도 함께 저장한다(`textInImage`).
  - 저장 형식: `media: { img: { "쪽 번호": { name, fx, fy, data: "data:image/jpeg;base64,…" } }, aud: {…} }`. `fields`는 그대로라 예전 JSON도 그대로 열린다.
  - **그림은 줄여서 담는다**: 긴 변 최대 1600px JPG(품질 0.9, 투명한 곳은 흰색) — 7단계 플립북 파일이 쓰는 크기와 같다. 원본 PNG를 그대로 넣으면 파일이 너무 커지기 때문(사용자의 1254×1254 PNG 10장 29.2MB → 그대로면 JSON 약 40MB, 줄이면 그림 약 5.3MB). 이미 작은 그림(긴 변 1600px 이하이면서 JPG이거나 600KB 이하)은 원본 그대로 담는다. 그래서 불러온 뒤 다시 저장해도 그림이 또 줄어들지 않는다. 브라우저와 컴퓨터에 있는 원본은 바뀌지 않는다.
  - 불러올 때: 파일에 그림이 있으면 이 브라우저의 5단계 그림을 **파일의 그림으로 통째로 바꾼다**(이미 그림이 있으면 확인창에 개수). 파일에 그림이 없으면(V8.5까지의 파일) 이 브라우저의 그림은 건드리지 않고, 5단계 이후까지 간 책이면 "이 파일에는 그림이 들어 있지 않습니다"라고 알려 준다.
  - 창 닫기 전 저장 안내도 그림을 함께 본다(`workSig` = 1~4단계 + 음성 + 그림의 쪽·이름·크기·자를 위치). V8.5에서 JSON을 받아 둔 사람은 그림이 그 파일에 없으므로 다시 저장하라고 묻는다.
  - 시험: 사용자의 실제 그림 10장(1254×1254 PNG, 29.2MB) + 음성 6개 → JSON 8.2MB, 저장 0.3초·불러오기 0.3초. 모두 지운 뒤 불러와 그림 10·음성 6·자를 위치 복원, 새로고침 뒤 유지, 7단계 책 생성 확인. 원본 대비 화질 PSNR 약 35dB.
  - 한계: 불러온 그림은 줄인 JPG다(원본 PNG가 아님). 원본 파일은 컴퓨터에 따로 보관해야 한다.

- **4단계 위에 "추가 에셋"**: 4단계가 3단계 에셋 표에 없는 배경을 `(신규)`로 적으면, 전에는 빨간 점선 칩("3단계 표에 없음")만 뜨고 그 배경의 참조 프롬프트는 어디에도 없었다. 사용자 지적: "단계별로 진행하는데 왜 갑자기 없는 게 만들어지나, 필요해서 만들었다면 4단계 위에 추가 에셋이라고 넣어 주든가". 이제 4단계가 새 배경을 쓰면 **그 배경의 참조 이미지 프롬프트도 함께 만들어** 장면 카드 위 "추가 에셋" 상자에 3단계 에셋 카드와 같은 모양으로 보여 준다(설명 · 쓰이는 쪽 · 크기 줄 · [프롬프트 복사]). 추가 에셋이 없으면 상자는 보이지 않는다.
  - 왜 새 배경이 생기나: 3단계와 4단계는 AI에게 따로 묻는다. 3단계가 원고의 배경을 하나 빠뜨리면 4단계가 그 쪽을 그릴 배경이 없어 `(신규)`로 적는다. 4단계 지시문은 "먼저 에셋 표에서 고르고, 어떤 장면으로도 그릴 수 없을 때만 새로 만든다"로 좁혔다.
  - 결과칸 형식: 4단계 결과칸 하나에 표가 두 개 들어간다. 장면 표 아래에 `[추가 에셋]` 제목 줄과 `| 종류 | 에셋 이름 | 설명 | 참조 이미지 프롬프트 |` 표(3단계 표와 같은 형식). 입력칸·JSON 형식은 그대로라 예전 JSON도 그대로 열린다. 첫 칸이 `캐릭터/장면/도구`인 줄을 추가 에셋으로 읽으므로 제목 줄이 빠져도 읽힌다(`s4Parts`).
  - 칩: 추가 에셋을 쓰는 쪽은 주황 점선 `(추가) 이름` — 누르면 그 참조 프롬프트가 복사된다. 빨간 점선은 "이름을 못 찾음"(3단계 표에도 추가 에셋에도 없는 이름)으로 뜻을 좁혔다. 범례 문구도 그렇게 바꿨다.
  - 3단계 표에 같은 이름이 이미 있으면 3단계 것을 쓰고 추가 에셋에서는 뺀다(사용자가 추가 에셋을 3단계 표로 옮겨 적은 경우).
  - V8.5까지 만든 4단계 결과에 `(신규)`가 있으면 추가 에셋 표가 없으므로 빨간 칩 그대로다. [장면 생성]을 다시 해야 추가 에셋으로 만들어진다.
  - **확인 못 한 것**: Gemini가 실제로 이 형식(표 두 개)대로 답하는지. API 키 없이 시험해서, 결과칸에 예시 표를 넣어 화면만 확인했다.
- **V8.5의 오류 수정 — "크기: NaNKB"**: V8.5에서 파일 크기를 적는 함수를 `sizeText`라는 이름으로 새로 넣었는데, 책 크기를 적는 기존 `sizeText()`와 이름이 같아 뒤의 것이 앞의 것을 덮어썼다. 그래서 V8.5 배포본(2026-11-19 오전)에서는 3단계 장면 카드의 크기 줄, 4단계 최종 프롬프트의 `[화풍: …, 크기: …]`, 장면 칩 복사, 3단계 에셋 생성 지시문의 책 크기가 모두 `NaNKB`로 나왔다. 파일 크기 함수 이름을 `fileSizeText`로 바꿔 고쳤다. V8.5에서 복사해 둔 프롬프트에 `NaNKB`가 들어 있으면 다시 복사해야 한다. (한 파일 앱에서는 같은 이름의 함수가 오류 없이 덮어써지므로, 함수를 새로 넣을 때 같은 이름이 있는지 먼저 검색할 것)

## V8.5 (2026-11-19)

- **JSON 저장에 6단계 음성이 함께 들어간다**: 전에는 JSON에 1~4단계 글만 들어가서, 음성을 올리고 JSON으로 저장한 뒤 다른 컴퓨터·브라우저(또는 [전체 초기화] 뒤)에서 불러오면 음성이 없었다(사용자 보고). 이제 음성 파일을 글자(data: 주소)로 바꿔 JSON의 `media.aud`에 넣고, 불러올 때 6단계에 되살린다. 쪽·순서·파일 이름·길이가 그대로 돌아온다.
  - 저장 형식: `media: { aud: { "쪽 번호": [{ name, dur, data: "data:audio/…;base64,…" }, …] } }`. `fields`는 그대로라 예전 JSON도 그대로 열린다.
  - 불러올 때: 파일에 음성이 있으면 이 브라우저의 6단계 음성을 **파일의 음성으로 통째로 바꾼다**(이미 음성이 있으면 확인창에 개수를 알려 준다). 파일에 음성이 없으면(예전 파일 등) 이 브라우저의 음성은 건드리지 않는다. 파일을 다 읽은 뒤에 "바뀝니다, 계속할까요?"를 묻도록 순서를 바꿨다(못 읽는 파일이면 지금 내용을 건드리지 않음).
  - 저장·불러오기 뒤 버튼 아래에 결과 한 줄: "저장했습니다: ○○.json (3.2MB · 6단계 음성 6개 포함)".
  - 창 닫기 전 저장 안내(V8.4)도 음성을 함께 본다: JSON을 받은 뒤 음성을 올리거나 빼거나 순서를 바꾸면 다시 "저장 안 됨"(`workSig` = 1~4단계 지문 + 음성의 쪽·순서·이름·크기 지문). 음성이 없으면 V8.4와 같은 값이라 전에 저장해 둔 사람에게 다시 묻지 않는다.
  - **파일이 커진다**: 음성은 원본 그대로, 글자로 바꾸면서 약 1.33배가 된다(음성 합계 6MB → JSON 약 8MB). 저장할 때 잠깐 "저장하는 중…".
  - **5단계 그림은 여전히 JSON에 들어가지 않는다**(이 브라우저 IndexedDB에만). 다른 컴퓨터에서는 그림을 다시 올려야 한다. (V8.6부터 그림도 JSON에 들어간다)
  - 한계: 음성이 아주 크면(합계 수백 MB) 브라우저가 한 번에 다룰 수 있는 글자 길이를 넘어 저장·불러오기가 실패할 수 있다 — 그때는 오류 문구를 보여 준다. 실제 한도는 재 보지 않았다.

## V8.4 (2026-11-18)

- **창을 닫기 전에 JSON 저장 안내**: 1~4단계 내용이 마지막으로 JSON을 받거나 불러온 때와 다르면, 창을 닫거나 새로고침할 때 브라우저의 "나가시겠습니까?" 확인창이 뜬다. 거기서 [취소]를 누르면 "잠깐! 작업 내용을 파일로 저장하셨나요?" 창이 떠서 [작업 내용 JSON으로 저장]을 바로 누를 수 있다.
  - 브라우저 확인창의 문구는 브라우저가 정한다(사이트가 바꿀 수 없음). 그래서 "JSON"이라는 말은 그다음 창에 나온다. 창이 닫히는 순간 파일을 자동으로 받게 할 수도 없다.
  - 저장 여부는 `state.jsonSig`(1~4단계 입력·결과의 길이:해시)로 기억한다. JSON을 받거나 모든 칸이 든 JSON을 불러오면 "저장됨", 그 뒤 한 글자라도 바뀌면 다시 "저장 안 됨". 내용이 비어 있으면 묻지 않는다. [전체 초기화] 뒤 새로 읽을 때도 묻지 않는다.
  - 5·6단계 그림·음성은 JSON에 들어가지 않으므로 이 안내와 무관하다. (V8.5부터 음성은 JSON에 들어가고 이 안내도 음성을 함께 본다. 그림은 그대로 무관)

## V8.3 (2026-11-10)

- **한 쪽에 음성 여러 개**: 6단계에서 쪽마다 음성을 여러 개 넣을 수 있다. 쪽 카드의 [음성 추가](여러 파일 선택 가능)나 카드에 끌어다 놓기는 기존 음성 **뒤에 보태고**, 위쪽 끌어다 놓기·[음성 여러 개 고르기]는 파일 이름의 쪽 번호-순서(`3p-1.mp3`, `3쪽_2.mp3`, `p03-1.mp3` — 앞 숫자가 쪽)대로 넣되 이미 음성이 있는 쪽은 **통째로 바꾼다**(확인창). 카드 안에서 음성마다 미리 듣기·▲▼ 순서 바꾸기·✕ 빼기, [모두 빼기]. 배지 "음성 3개", 통계에 음성 개수·총 길이.
  - 7단계와 받은 플립북 파일: 그 쪽을 펼치면 1번부터 차례로 이어서 읽고(같은 쪽 음성 사이 0.35초), 다 읽은 뒤 자동 넘김. 안내 줄에 "3쪽 2/3 읽는 중". 창 크기가 바뀌어도 읽던 음성부터 이어짐.
  - 저장 형식: IndexedDB `aud:n` = `{ clips: [{ blob, name, dur }, …] }`. 예전(쪽마다 하나) 기록은 읽을 때 목록으로 바꿔 그대로 쓴다. 플립북 데이터의 `aud`는 주소 배열(보기 코드는 문자열 하나도 받음).

## V8.2 (2026-11-09)

- **장면(배경) 프롬프트에 책 크기·비율 자동 첨부**: 3단계 장면 카드와 4단계 칩에서 복사하면 프롬프트 끝에 `[크기: 가로 210mm × 세로 210mm (비율 1:1, 정사각형) — 동화책 한 쪽과 같은 비율의 배경 그림으로]`가 붙는다(카드에도 주황 표시). 전에는 4단계 최종 프롬프트에만 크기가 붙어서, 배경 참조 그림이 가로로 긴 비율 등 책 쪽과 다른 비율로 나왔다. 캐릭터 시트·도구(흰 배경 참조용)에는 붙이지 않는다. 가로·세로를 고치면 카드가 바로 바뀐다.
  - 4단계 최종 태그도 `크기: 가로 210mm × 세로 210mm (비율 1:1, 정사각형)`처럼 비율을 함께 적는다(이미지 생성기는 mm보다 비율을 본다).
  - 에셋 생성 프롬프트(3단계)에는 "배경은 책 쪽 비율(정사각형/가로형/세로형)에 맞는 구도로, 숫자는 쓰지 말 것"을 넣었다. 크기를 비워 두면 이 문장은 빠진다.

## V8.1 (2026-11-09)

- **2단계·3단계 순서 교체**: 1 줄거리 → **2 페이지 원고** → **3 에셋** → 4 장면 프롬프트. 원고를 먼저 쓰고, 에셋(캐릭터·장면·도구)은 그 원고를 페이지마다 읽어서 뽑는다. 그래서 장면(배경) 목록이 실제 원고와 맞고, 4단계에서 `(신규)` 장면이 뜰 일이 줄어든다. 원고 프롬프트는 에셋 표 없이 줄거리만으로 쓰되 "캐릭터·장소·물건 이름을 끝까지 같게" 쓰도록 요청한다.
  - 입력칸 id(`s2*`=에셋, `s3*`=원고)와 저장 JSON 형식은 그대로라 V8 JSON을 그대로 불러올 수 있다. 화면 순서만 `STEP_PANEL`/`STEP_RESULT` 매핑으로 바꿨다.
- **전체 초기화 버튼** (맨 아래 JSON 저장 옆): 확인창 뒤 1~4단계 입력·결과와 5·6단계에 올린 그림·음성(IndexedDB)을 모두 지우고 새로 읽는다. API 키와 모델 선택은 남긴다.

| 7. 오디오 플립북 | 책장을 넘기면 0.45초 뒤 그 쪽 음성을 처음부터 읽는다. 소리 듣기/멈춤, 다시 듣기, 처음으로, 자동 넘김(다 읽고 1.5초 뒤 다음 쪽), 전체 화면, 키보드 ← → 와 스페이스. ① **펼침면**: 표지 → (왼쪽 그림 · 오른쪽 원고) → 뒤표지. 좁은 화면은 한 쪽씩(그림 → 글), 같은 쪽의 그림에서 글로 넘어갈 때 소리가 끊기지 않음 ② **그림만**: 표지 → 그림 쪽들 → 뒤표지. 넓은 화면은 두 쪽이 펼쳐지고 왼쪽 → 오른쪽 차례로 읽음(쪽 사이 0.5초), 좁은 화면은 한 쪽씩. 쪽 수가 홀수면 뒤표지 앞에 빈 쪽을 넣음 |
| 7단계 · 플립북 파일로 받기 | 완성된 플립북을 **HTML 파일 하나**로 받는다. 그림(긴 변 최대 1600px JPG, 품질 0.86 — 펼침면은 책 비율로 잘라서, 그림만은 자르지 않고 책 비율 종이 위에 전체)·음성(원본 그대로)·page-flip 라이브러리 원문·보기 코드(`flipbookViewer`)가 모두 들어 있어 인터넷 없이 더블클릭으로 열린다. 그림·음성이 빠진 쪽이 있으면 받기 전에 알려 준다 |

- 책장 넘김: [page-flip 2.0.7](https://github.com/Nodlik/StPageFlip) (MIT, jsDelivr CDN) — story-flipbook이 쓰는 react-pageflip의 바탕 라이브러리
- 그림·음성 보관: 브라우저 IndexedDB `storybookAudioFlipbook_v8` (서버로 보내지 않음, API 키 필요 없음). JSON 저장에도 함께 들어간다 — 음성은 V8.5부터(원본 그대로), 그림은 V8.6부터(긴 변 최대 1600px JPG로 줄여서), 표지 그림은 V8.9부터(그림의 0쪽)
- 1~4단계는 V7과 같다(V8.1에서 2·3단계 순서만 교체). 단, 원고 표의 머리글 `| 페이지 | 원고 |` 이 원고 카드(와 1쪽 원고)로 읽히던 문제를 고쳤다 (V7에는 그대로 있음)

## 시험한 것 (2026-11-01, 이 PC의 Claude 앱 내장 브라우저 · Chromium 152, 로컬 서버)

- 「겁많은 토끼의 용감한 도전」 JSON + 그림 6장(순서를 섞어 끌어다 놓기) + 가로 그림 1장(2쪽 교체, 좌우 위치 25%) + 음성 6개(1p~6p, 순서 섞음) → 모두 쪽 번호대로 들어감
- 새로고침 뒤에도 그림·음성·자를 위치 유지
- 넓은 화면: 표지 → [▶ 소리 듣기] → 1쪽 펼침면에서 1쪽 음성 재생, [다음 ▶] → 2쪽 음성 처음부터, 자동 넘김으로 2쪽 → 3쪽 넘어가며 3쪽 음성 재생
- 휴대폰 크기(375px): 한 쪽씩 보기로 바뀌고 쪽 위치 유지, 1쪽 그림 → 1쪽 글로 넘겨도 음성이 이어짐, 멈춘 상태에서 화면 크기가 바뀌어도 저절로 재생되지 않음
- ◀▶ 바꾸기·빼기 동작, 콘솔 오류 없음
- 플립북 파일로 받기: 토끼 책 6쪽(PNG 원본 약 19MB) → 4.77MB HTML, 그림 6·음성 6 포함, 바깥 주소는 글꼴(Google Fonts) 하나뿐(없으면 기본 글꼴). 받은 파일에서 표지 → [▶ 소리 듣기] → 1쪽 재생, [다음 ▶] → 2쪽 재생, 멈춤 확인 (로컬 서버로 열어 시험)
- 사용자가 받은 파일(펼침면)을 자기 PC에서 열어 "잘 돼" 확인 (2026-11-01)
- 그림에 원고가 들어 있음(네): 5단계 질문 표시·저장·7단계와 연결, 가로 그림이 잘리지 않고 전체 표시·자를 위치 막대 숨김, 플립북 8장(표지·그림 6·뒤표지, 글 쪽 없음), 1–2쪽 펼침에서 1쪽 → 2쪽 차례로 읽고 자동 넘김으로 3–4쪽, 휴대폰 크기에서 한 쪽씩, 쪽 수 5일 때 빈 쪽 추가, 받은 파일에서 그림 전체(가로 그림 1600×1600 종이 위)·1쪽 재생. '아니요'로 바꾸면 다시 글 쪽 6장 포함 14장
- **안 해 본 것**: 실제 크롬·엣지·사파리(아이폰·아이패드), 실제 파일 고르기 창(시험은 끌어다 놓기 이벤트로 함), 큰 그림 수십 장, 전체 화면 버튼, 받은 파일을 카톡·아이폰에서 연 경우, 실제 캔바에서 원고를 넣은 그림

## 고칠 때 주의

- 앱 전체가 `<script>` 안에 있으므로, 받는 파일을 만드는 문자열에 닫는 script 태그를 그대로 쓰면 앱이 깨진다. `<\/script>` 로 쓴다 (`buildExportHtml`)
- 책 화면은 `flipbookViewer` 하나를 앱 7단계와 받은 파일이 같이 쓴다(받은 파일에는 `toString()`으로 옮겨짐). 그래서 이 함수 안에서는 앱의 변수·함수를 쓰면 안 된다. 책 화면 스타일은 `VIEWER_CSS`(앱은 실행할 때 `<style>`로 넣고, 받은 파일에도 그대로 들어감)

## 4단계 복사 버튼이 복사하는 내용

```
(장면 프롬프트 본문)
[참조 이미지 첨부] 캐릭터: 민호, 책벌레 · 장면: 밤의 도서관 열람실 · 도구: 반짝이는 글자책 — 첨부한 참조 이미지 속 캐릭터·장면·도구의 외형, 색, 구조를 그대로 유지할 것
[화풍: ..., 크기: 가로 210mm × 세로 210mm]
```

칩(에셋 이름)을 누르면 그 에셋의 3단계 참조 프롬프트가 복사된다. `(신규)`로 표시된 장면은 3단계 표에 없는 배경이므로 필요하면 3단계 표에 추가한다. (V8.6부터: 새 배경은 4단계 위 "추가 에셋"에 참조 프롬프트와 함께 나오고, 칩은 `(추가)`로 표시된다)

## 표 형식 (직접 고칠 때)

- 3단계(에셋): `| 종류 | 에셋 이름 | 설명 | 참조 이미지 프롬프트 |` — 종류는 `캐릭터` / `장면` / `도구`
- 4단계: `| 페이지 | 사용 에셋 | 장면 프롬프트 |` — 사용 에셋은 `캐릭터: 이름1, 이름2 / 장면: 이름 / 도구: 이름`
  - V8.6부터: 새 배경이 있으면 그 아래에 `[추가 에셋]` 줄과 3단계와 같은 형식의 표가 이어진다
